TECHNICAL PLAN

Clarify before the plan

Stop the plan from guessing the decisions only you can make. Appetite: M. Risk: low.
01

Approach

Approving Requirements no longer drafts the plan. It opens a Clarify round: Claude proposes the decisions the plan would otherwise guess, each as one question carrying two to four concrete options. Applying the answers writes ## Resolved Decisions into plan.md, and only then does it draft.

Two alternatives were rejected. Asking mid-run means the answer arrives after the plan has already committed to a shape. A free-text questionnaire means nobody fills it in.

03

Main process

One shape crosses the IPC boundary, and it is the whole contract:

type SpecQuestion = {
  id: string;          // "Q1"
  prompt: string;
  options: string[];   // 2–4, each a full sentence
  answer?: string;     // set once resolved
};

plan:draft gains noStops: boolean. Quick Plan, Revise and Improve pass true and never stop; every other caller passes false and stops once.

04

Renderer

The Plan stage becomes two sub-tabs — Clarify and plan.md — the way Build already holds Task list, tasks.md and Ship. Approving Requirements lands on Clarify.

  • Every question is a card. Its options are chips, answerable on keys 1 through 9.
  • Other… opens free text; Ask Claude picks an option and says why.
  • Apply decisions writes the section and drafts the plan in one action.
05

Key implementation details

The specifics an executor would otherwise have to guess.

  • A plan run stops at most once. The second run through the same spec drafts whatever it has.
  • Questions are written to ## Open Questions in plan.md, not held in memory — a crash loses nothing.
  • An option chip is a full sentence, so the resolved decision reads as prose in the plan.
  • Answering resolves the question in place; the list never reorders under the cursor.
06

Verification

Every acceptance criterion, and how it is proven.

AC-1 WHEN Requirements is approved THEN the stage opens on Clarify — asserted in the stage-transition test.
AC-3 WHEN an option is clicked THEN that question resolves in place — asserted on the rendered card.
AC-6 IF a plan run returns questions THEN the stage flips back to Clarify — asserted on the run handler.
07

Tasks

Five changes across three waves. Wave 2 depends on the parser landing.

WAVE 1
T1  Parse Open Questions into SpecQuestion[] — outcome: a malformed list yields zero questions, never a crash.
T2  Teach the drafting prompt to emit options — outcome: every question ships 2–4 of them.
WAVE 2
T3  Question cards with chip options and keys 1–9 — outcome: a round of six is answerable without the mouse.
T4  Land Approve-Requirements on Clarify — outcome: no run starts until decisions are applied.
WAVE 3
T5  Write Resolved Decisions, then draft — outcome: the drafted plan cites the answers it was given.
