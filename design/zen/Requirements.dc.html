REQUIREMENTS

Clarify before the plan

A plan that guessed is a plan you have to re-read. Ask first.
01

Introduction

Today, approving Requirements starts a plan run immediately. Where the requirements leave a decision open — a storage shape, an interaction, a boundary — the plan picks one silently and commits the whole document to it. The reader finds out three sections later, in a code block.

This capability puts one short round of questions between the two gates. Claude names the decisions it would otherwise make alone, you answer them in a few clicks, and the plan is drafted against your answers.

02

User stories

US-1

As someone writing a spec, I want to settle the decisions the plan depends on before it drafts, so that the plan commits to my answer instead of guessing.

US-2

As a reviewer, I want every question to arrive with concrete options, so that answering is one click and not an essay.

US-3

As someone in a hurry, I want to skip the questions entirely, so that a quick plan still lands without stopping.

03

Acceptance criteria

EARS notation. Each one names an event and one observable outcome.

AC-1
US-1

WHEN the user approves Requirements THEN the system SHALL open the Clarify tab, unless Resolved Decisions already exists.

AC-2
US-2

WHEN Claude surfaces a decision THEN each question SHALL carry two to four concrete options, each with its tradeoff.

AC-3
US-2

WHEN the user clicks an option THEN the system SHALL resolve that question with the option text, in place.

AC-4
US-2

WHILE the Clarify panel is on screen THE SYSTEM SHALL answer the first open question on keys 1 to 9.

AC-5
US-1

WHEN the user applies the decisions THEN the system SHALL write Resolved Decisions and draft the plan if it is still a stub.

AC-6
no story

IF a plan run returns questions instead of a plan THEN the system SHALL switch the stage back to Clarify.

AC-7
vague

WHILE the panel is open THE SYSTEM SHALL feel responsive and stay easy to use.

04

Out of scope

  • Questions during the Build stage — a running task asks in its terminal, not here.
  • More than one clarify round per spec.
  • Editing an answer after the plan has been drafted; revise the plan instead.
05

Non-functional requirements

  • A round of six questions is answerable from the keyboard alone.
  • Questions survive a crash: they live in plan.md, not in memory.
  • No question round costs a Claude run on its own — it rides the plan run that produced it.
